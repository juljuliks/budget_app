# План улучшений budget_app

Только то, что ещё не сделано (сверено с кодом 9 октября 2026). Порядок этапов: риск потери данных → надёжность →
производительность → функции → полировка. Каждый пункт — отдельный коммит с `tsc` + `jest`.

## Этап 1 — Не потерять данные (P0)

1. **Резервная копия / восстановление / экспорт.** Ничего нет, `allowBackup="false"` в `AndroidManifest.xml` — новый
   телефон = потеря всего.
   - Настройки → «Резервная копия»: `VACUUM INTO` копия `app.db` → Share/SAF; «Восстановить» из файла (с проверкой
     схемы и копией текущей БД).
   - «Экспорт CSV» операций (дата, сумма, валюта, категория, мерчант, заметка).
   - Android Auto Backup с `dataExtractionRules`, только БД.
2. **Локальная release-сборка без ключа** подписывается debug-ключом (`android/app/build.gradle`, `signingConfigs.debug`
   как запасной). CI без секретов уже останавливается; локально — падать без `BUDGETAPP_RELEASE_*`, кроме явного
   `-PallowDebugSigning`.
3. **Версия в Настройках.** `versionCode` = число коммитов, `versionName` = `1.0.N` уже есть; показать её в листе
   «Настройки».
4. **Дубли SMS + push** (`src/ingest.ts`): проверка «двойника» и INSERT — отдельные запросы очереди, при одновременном
   приходе вставятся оба. Обернуть в `db.transaction`; `abs(occurred_at - ?) <= ?` → `BETWEEN` (использует индекс).
5. **Разбор push**: тело = `title\ntext` (`BankPushListener.kt`), а `PAYMENT`/`CONVERSION`/`ONE_TIME_CODE` якорятся на
   `^` (`tbc.ts`) → push «Payment» классифицируется иначе, OTP и конвертации не отсекаются. Парсить title и text
   отдельно; повтор того же уведомления дедуплицировать по `sbn.key`.
6. **Многошаговые записи без транзакции**: `assignCategory` (`src/assign.ts`), `setMerchantCategory`
   (`src/db/merchants.ts`), `setPlanBudget` / `setPlanAmount` (`plans.ts`), `balance.ts`.

## Этап 2 — Надёжность и обратная связь

1. **Ошибки видны пользователю**: тост `toastError` есть в 15 файлах, но ~80 `console.error` по-прежнему молчат для
   пользователя (загрузки экранов, фоновые обновления). Где действие пользователя — тост.
2. **Вечные спиннеры**: при ошибке загрузки — «Не удалось загрузить · Повторить»; «Операция не найдена» в карточке
   (открытие удалённой из уведомления).
3. **Отмена удаления**: тост «Отменить» для операции и пункта плана (обычный пункт удаляется без подтверждения).
4. **Курсы валют** (`src/db/fx.ts`): таймаут запроса, кэш неудач (офлайн — до 40 запросов на каждую загрузку
   статистики), проверка даты ответа НБГ.
5. **Нераспознанные SMS** молча `ignored`: таблица `unparsed_messages` + экран «Не распознано» с повторным разбором
   (смена формата TBC, валюта не GEL/USD/EUR в поездке).
6. **Гонки загрузок в HistoryView** (StatsView, PeriodStatsView, PlanView уже на `useLatestRequest`).

## Этап 3 — Производительность

1. **Статистика**: один экран «за день» — ~8–9 `periodStats` + 1–3 `monthStats` ≈ 60–90 SQL-запросов.
   - `spendByDayCategory(from, to, currency)`: траты агрегированы в SQL по (день, категория, валюта), конвертированы
     один раз; `loadNorms` считает окна префиксными суммами; планы — `SELECT … FROM plan_items WHERE ym IN (…)`.
   - Кэш конвертера (`makeConverter` читает всю таблицу курсов на каждый вызов), сброс при вставке курсов.
   - Курсы в фоне: статистика рисуется по кэшу, недостающие курсы докачиваются, затем `emitTransactionsChanged`.
   - `planHistory` / `averageFullMonths` — агрегировать в SQL.
   - Замер: счётчик запросов в драйвере в dev-режиме, до/после.
2. **Индексы** (новая миграция): `transactions(category_id)`, `(merchant_key, occurred_at)`, `(kind, refund_settled_at)`.
3. **Поиск** (`searchTransactions`) читает строки с `raw_sms` в JS на каждый ввод → колонка `search_text`
   (заполняется при вставке) + фильтр в SQL с `LIMIT`.
4. **Импорт SMS** пачками в одной транзакции; `autoCategorizeRefunds` без N+1; `getMerchant` — одна строка вместо
   `listMerchants()` целиком.
5. **Список операций**: `React.memo` для `TransactionItem`, стабильные `renderItem` и обработчики.

## Этап 4 — Функции

1. **Редактирование операции целиком**: дата (`RangeCalendar` уже есть), мерчант / описание, тип; в ручной операции —
   перевод / снятие (сейчас редактируются сумма, валюта, категория, заметка).
2. **Разделение операции** на несколько категорий (чек супермаркета: еда + хозтовары).
3. **Доходы и сбережения**: доход − расход по месяцам, процент сбережений, изменение баланса карты за месяц (сейчас
   доход месяца виден только в плане).
4. **Напоминания об обязательных платежах**: «Аренда не оплачена, обычно до 5-го» (уведомления 80% / 100% уже есть).
5. **Перенос остатка** категории на следующий месяц (опция на категорию; внутри месяца пересчёт лимитов уже есть).
6. **Онбординг**: объяснение SMS перед запросом разрешений, выбор валюты, первые категории и план; пустые состояния с
   действием («Добавить вручную», «Составить план»).
7. **Другие банки** (Bank of Georgia): выбор парсера по отправителю.
8. **Пуши TBC**: точное имя пакета вместо `contains("tbc")` и настоящие тексты пушей в фикстуры.
9. **Парсер**: снятие наличных и покупка в USD разобраны по догадке — сверить с настоящими SMS.
10. **Переименование категории** меняет имя во всех месяцах — спросить, оставлять ли старое в прошлых.
11. **Префиксные правила мерчантов** (`prefix WOLT`) — работают, но в интерфейсе их не видно и не изменить.

## Этап 5 — Баланс карты и деньги «к распределению»

Зарплата приходит в крипте, на карту выводится P2P раз в 2–3 дня (в SMS — «Deposit Money»). Депозит — просто
депозит, баланс карты синхронизирован с банком (уже есть: `src/db/balance.ts`).

- **Сверка:** ожидаемый баланс (прошлый ± операции) не совпал с пришедшим в SMS → «Расхождение 25 ₾ — пропущенная SMS
  или комиссия?» с кнопкой «Добавить трату».
- **«К распределению»** = баланс карты − остатки по категориям плана; запланировано больше, чем есть, — предупреждение.
- **«Можно тратить сегодня»** = min(остаток повседневных трат, баланс карты) / оставшиеся дни — одна цифра на главном
  экране; формула пересчёта лимитов уже есть (`partsOf` в `src/ui/stats/norms.ts`), осталось сложить и вывести.

## Этап 6 — Фичи как у похожих приложений

1. **Копилки под нечастые траты**: «Отпуск 3000 ₾ к июлю», «Страховка 600 ₾ в год» — сколько откладывать в месяц,
   прогресс.
2. **Бюджет сразу после операции** в уведомлении: «Бары: на этой неделе осталось 20 ₾».
3. **Подписки и регулярные платежи** — автопоиск (один мерчант, похожая сумма каждый месяц), сумма в месяц и в год,
   предупреждение о подорожании.
4. **Тренды по категориям** — график за 6–12 месяцев, «этот месяц vs среднее за 3 месяца» («Бары +40%»).
5. **Отчёт за месяц**: добавить топ мерчантов и сравнение с прошлым месяцем (сбережения и «Что можно улучшить» уже есть).
6. **Аналитика мерчанта** в карточке: средний чек (всего и число покупок уже есть).
7. **Теги поверх категорий** — «#батуми-2026»: итог по событию через несколько категорий.
8. **Общие траты и долги** (как Splitwise): возврат закрывает долг и не считается доходом.
9. **Наличные** — снятие как перевод на счёт «Наличные», траты списываются оттуда быстрым вводом.
10. **Поездки** — траты в чужой валюте в отдельный бюджет вне месячного плана.
11. **Цели** — накопления с прогнозом («при текущем темпе — к марту»), серии «N дней без перерасхода».

## Этап 7 — UX и доступность

1. **Тёмная тема**: палитры light/dark в `theme.ts` + `useColorScheme`; убрать захардкоженные `#FFFFFF` (14 мест в `src/ui`).
2. **Крупный шрифт системы**: `maxFontSizeMultiplier` для Segmented, центра диаграммы, заголовков.
3. **Подписи для TalkBack**: строка операции целиком (мерчант, сумма, категория), стрелки периода, раскрытие в Истории, чипы.
4. **Контраст и размеры нажатия**: неактивная стрелка (#E5E7EB на белом), иконки 30dp → 48dp.
5. **Вкладка «План»** не слушает `onTransactionsChanged`; отступ под FAB в PlanView; переход Статистика ↔ План без
   скачка месяца.

## Этап 8 — Код и инструменты

1. **ESLint + Prettier** (`@react-native-community/eslint-config`, `react-hooks`), скрипты `typecheck` / `lint` / `format`.
2. **Размер APK (~23 МБ)**: собираются все 4 ABI (`reactNativeArchitectures` в `android/gradle.properties`) → только
   arm64 или ABI splits; позже R8 с keep-правилами (Notifee, quick-sqlite).
3. **Скрипты не только под macOS**: `java_home` только если есть, образ эмулятора по `uname -m`, `OUT_DIR` вместо `~/Desktop`.
4. **БД**: `foreign_keys` сейчас OFF — включить после миграций или периодический `foreign_key_check`; CHECK на
   `kind` / `amount`; миграция 9 не должна зависеть от текущего парсера; миграции только при старте UI.
5. **Чтение без побочных эффектов**: `getPlanBudget` / `listPlan` создают план месяца (`ensureMonthPlan`) — только из
   команд плана и при старте; `cardBalance` не пишет настройку при чтении.
6. **Одно правило «что считается тратой»** (`src/db/spend.ts`): `SPEND_KINDS`, знак возврата, «непривязанный
   возврат» — сейчас продублировано в ~6 местах (`plans.ts`, `categorySummary`, `getMerchant`, `backfillRule`, `balance.ts`…).
   Хелперы `placeholders()` вместо ручной сборки списков; общий `buildCategoryStats` для `monthStats` / `periodStats`.
7. **Большие компоненты**:
   - `TransactionsList.tsx` (~760 строк): хуки `useTransactionFilters`, `useSelection`; `SearchBar` (общий с
     Мерчантами), `BulkBar`; разбор удаления категории — на тех же хуках. Данные списка и заголовок раздела уже вынесены.
   - `PeriodStatsView.tsx` (~870): `PeriodCategoryRow`, `LimitEffect`, `CategoryInfo`; текстовые хелперы → `stats/periodText.ts` с тестами.
8. **Общие модули UI**: `ui/dates.ts` (массивы месяцев в падежах и дней недели — несколько копий), одна карта «дней
   в ритме», `formatPercent` / `formatTotals`, типизированный `useOpenTransactions()` вместо `navigate(… as never)`
   (`CategorySheet`), цвета `onAccent` / `accentBg` в теме, общий `statsStyles.ts`.
9. **Архитектура**: `loadNorms` (работа с БД) из `ui/stats/norms.ts` → `src/stats/`; data-слой не возвращает тексты и
   цвета UI; загрузка курсов из `db/fx.ts` → `src/fx/`; `emitTransactionsChanged` — из одного места (команды).
10. **Мёртвый код**: `export default {…}` в 14 модулях, колонка `is_archived`, `'GEL'` → `BUDGET_CURRENCY`.
11. **Тесты**: расчёты из `.tsx` (StatsView, HistoryView, PlanView) → `.ts` с тестами; покрытие в `jest.config.js`.
12. **RN 0.71 → 0.73+** вместе с заменой `react-native-quick-sqlite` (op-sqlite): targetSdk 34+, AGP 8 — отдельный проект.

## Как проверять

- `npx tsc --noEmit`, `npm test`; на каждое исправление — тест (ingest в транзакции и дубли SMS/push, fx таймаут,
  число запросов статистики, бэкап/восстановление на базе в памяти). Кейсы — в [tests/README.md](tests/README.md).
- `npm run emulator` — установка поверх текущей версии, данные должны сохраниться; на телефон — только `adb install -r`.
- Push / SMS: `scripts/send_test_sms.sh`, `tests/e2e/run.sh`.
