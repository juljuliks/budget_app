# План тестов · 8. Уведомления · на устройстве (Maestro и вручную)

Обозначения, Дано / Шаги / Ожидается и где что проверяется — [tests/README.md](../../README.md).

### 8.1 Новая операция без категории

**8.1.5 Кнопка категории**
- Категория назначена без открытия приложения, уведомление убрано.
- У мерчанта не было категории → она становится его.
- Может прийти уведомление о лимите.
- Где: Maestro `notification-buttons`.

**8.1.6 Тап / «➡️ К категориям»** — приложение открывает карточку операции; уведомление остаётся до выбора категории.
- Где: Maestro `notification-open`.

**8.1.7 Холодный старт** — тап по уведомлению при убитом приложении → после запуска открыта карточка.
- Где: Maestro `notification-open`.

### 8.2 Отчёт и итоги года

**8.2.4 Итоги года в шторке** — при запуске приложения запланировано «Итоги 2026» на 10:00 1 января (WorkManager);
его задание запущено принудительно (`run_scheduled`: перевод часов эмулятора его не запустит) → в шторке «Итоги 2026»,
«Отложено … ₾ за год · N% бюджета»; тап → итоги: с 24 декабря до 7 января — сторис «Ваш 2026 в цифрах», иначе
«Статистика за год» («По месяцам», «Отложено за …»).
- Где: Maestro `year-report` (seed `planned`).

### 8.5 Копилка не успевает

**6.5.12 В шторке** — копилка, которой не хватает до даты (seed `fund-late`: «👕 Одежда» 4 000 ₾ к концу
месяца через один); при запуске приложения — «👕 Одежда не успевает к …», «Копилке остаётся … в месяц из … —
сдвиньте дату или сумму»; тап → страница категории: «⚠ Не успеваете к …», «Копить … к …».
- Где: Maestro `fund-late`.

### 8.6 Обновление приложения

**8.6.1 Уведомление о новой версии** — сборка с версией старше последнего релиза (`./gradlew assembleRelease
-PemulatorSms -PBUDGETAPP_VERSION_NAME=1.0.100`), приложение запущено и закрыто; источник — пуш релиза (Firebase, тема
`releases`; без `google-services.json` его нет) или задача WorkManager раз в сутки (первый раз — через сутки после
запуска, нужна сеть); не чаще раза в сутки (`notified_at`). Новее установленной и не показана тостом → в шторке
«Доступна версия 1.0.N» · «Нажмите, чтобы обновить приложение», кнопка «Обновить» (канал «Обновления»); одна версия —
одно уведомление (`shared_prefs/app_update.xml`: `offered`). Тап (или `adb shell am start -n
com.budgetapp/.MainActivity --es budget_action update`) → тост «Скачивается…», APK в `cache/updates/update.apk`,
системная установка «Обновить?». Сборка «1.0-dev» не проверяет.
- Где: вручную (дождаться суток задача не может; тап проверен интентом выше).

**8.6.2 Установка без окна установщика** — после «Обновить» (или тапа по 8.6.1) APK ставится сессией `PackageInstaller`:
системный «Обновить?» над приложением → «Обновить» → приложение закрывается, окна «Приложение обновлено · Готово /
Открыть» нет; в шторке «Обновлено до 1.0.N» · «Нажмите, чтобы открыть приложение» (`MY_PACKAGE_REPLACED`; любая
установка поверх, и `adb install -r` тоже). Прошивки с своей оболочкой установки (Xiaomi) могут показать своё окно.
- Где: вручную на эмуляторе (проверено: 1.0.100 → 1.0.182 без окна; `adb install -r` → «Обновлено до 1.0.100»).
