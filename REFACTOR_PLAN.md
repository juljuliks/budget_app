# План: глубокий рефакторинг

Согласовано 25 ноября 2026. Цель — тот же функционал, но код, UI и производительность приведены к одним правилам, и эти
правила проверяются автоматически, а не на глазок. Обновление React Native (0.71 → 0.88, React 19) — отдельный проект
между этапами 5 и 6: React Compiler сам мемоизирует, FlashList v2 требует новой архитектуры — этап 6 делается уже на нём.

**Правило шагов.** Каждый шаг — отдельный коммит (коммит и пуш — по «пуш»). Перед коммитом: `npx tsc --noEmit -p .`,
`npm run lint`, весь `npm test` (через агента `test-runner`), затронуты SMS, уведомления, обновление — Maestro. Поведение
и вид не меняются, кроме UX-находок, которые вы приняли (этап 2). После шага — скилл `finish`.

   (`use*`; размер файлов и функций в `src/db` уже проверяется). Список нарушений — `docs/refactor/lint-baseline.txt`.
2. **Prettier.** `npm run format`; весь код — одним коммитом «No behavior change», в CI — `prettier --check`.
3. **`knip`.** Мёртвые экспорты и файлы — список в `docs/refactor/dead-code.txt` (удаляются на этапе 5).
4. **Замеры.**

## Порядок и почему так

Инструменты и замер — сначала, иначе «лучше» не доказать. Инвентаризация и UX-аудит — до правок, чтобы правки шли по
согласованному списку. Токены — до объединения компонентов (общий компонент сразу на токенах). Объединение — до
архитектуры слайсов (слайсы чистятся уже с общими компонентами). Производительность — после объединения: `memo` и
стабильность наводятся один раз в общем компоненте, а не в каждой копии. Обновление RN — после этапа 5 и до этапа 6: код уже
чистый, а мемоизацию и списки делаем сразу под React 19 и React Compiler, а не вручную дважды.

## Риски

- Визуальные расхождения при приведении к шкале — ловятся сравнением скринов до / после, каждое названо в коммите.
- `typescript-eslint` strict даст сотни предупреждений — включаем предупреждениями, ошибками только по мере очистки.
- Большие переносы файлов — `git mv`, импорты снаружи не меняются (папка с `index.ts`).
- Конфликты с параллельной работой (другие сессии пушат в `main`) — шаги маленькие, перед каждым `git pull --rebase`.
