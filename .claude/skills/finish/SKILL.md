# Готово ли изменение

Пройти по шагам по порядку. Шаг, которого изменение не касается, пропустить, но в итоге сказать, что он не нужен.
Все тексты — по-русски, в стиле соседних строк файла.

## 1. Глоссарий — [GLOSSARY.md](../../../GLOSSARY.md)

- Новое понятие в интерфейсе (кнопка, раздел, состояние) → строка: понятие, термин, «Не использовать».
  В «Не использовать» — только слова, которых действительно нет в интерфейсе в этом смысле (проверить grep по `src/`).
- Понятие убрано или переименовано → строку убрать / поправить.
- Новые и изменённые тексты интерфейса сверить с глоссарием: слово из «Не использовать» в том же смысле —
  расхождение. Не исправлять молча: показать пользователю варианты (поменять текст или глоссарий).

## 2. IMPROVEMENTS.md — [IMPROVEMENTS.md](../../../IMPROVEMENTS.md)

- Пункт сделан целиком → убрать. Сделан частично → оставить только то, что осталось.
- Изменение отменило пункт (функцию убрали) → убрать.
- По ходу нашлось, что стоит доделать позже, → дописать в подходящий этап.

## 3. README — [README.md](../../../README.md)

- Новый функционал или изменённое поведение → «Что умеет» (раздел по вкладке или месту в приложении).
- Новая команда, скрипт, папка → «Запуск» / «Где что».
- Исправление бага без нового поведения — README не трогать.

## 4. План тестов и тесты

Карта папки и покрытия — [tests/README.md](../../../tests/README.md).

1. Кейс в плане: проверяемое в Jest — `tests/screens/plan/N-*.md`, только на устройстве — `tests/e2e/plan/N-*.md`
   (со строкой «Где»). Формат: **N.N.N Название**, «Дано / Шаги / Ожидается», тексты дословно. Новый номер — следующий
   в подразделе; изменённое поведение — поправить старый кейс.
2. Таблица «Какой кейс где проверяется» в `tests/README.md` — строка, если появился новый файл теста или уровень.
3. Тест: экраны — `tests/screens/<раздел>.test.tsx` (хелперы `openApp`, `tap`, seed'ы из `tests/e2e/seeds.ts`);
   логика — `tests/logic/`; Maestro — только то, что Jest не может (скилл `maestro`). Баг → тест, который падает без
   исправления.
4. Прогон: `npx tsc --noEmit -p .` и нужные файлы Jest; весь `npm test` — через агента `test-runner`.

## 5. Архитектура — [ARCHITECTURE.md](../../../ARCHITECTURE.md)

- `npm run lint` — ошибок 0 (слои, размеры, хуки; с ошибкой релиз в CI не соберётся). Новый файл — в своём слое
  (скилл `architecture`).
- Новый слой, слайс или правило → ARCHITECTURE.md §1; новая папка → «Где что» в README.

Публичная документация здесь не правится — отдельно, скиллом `public-docs` (он находит изменения по коммитам с
прошлой сверки).

## Пуш (только по просьбе)

Сообщение коммита — что изменилось для пользователя (поведение, тексты в кавычках), а не только в коде: по ним
`public-docs` собирает изменения для документации. Без смены поведения — так и написать («No behavior change»).

Перед `git push` — `git fetch`; если `origin/main` ушёл вперёд — `git pull --rebase`, разобрать конфликты (переносы файлов,
пути импортов), прогнать `tsc` и тесты, затем пушить. Сказать пользователю, какие чужие коммиты пришли.

## Итог

Коротко пользователю: что обновлено по каждому шагу (или «не нужно»), какие расхождения с глоссарием найдены и ждут
решения. Коммит — только по просьбе («пуш»).
